# LOVE PASS 1.2.0

วันที่เตรียม release: 30 ตุลาคม 2026 · เปลี่ยนแปลงจาก `1.1.1`

## ชุดของขวัญและซองตาม tier

- แยกการ์ดข้อความจากของขวัญที่ส่งให้แฟน จัดชุดได้สองแบบ: เลือกคูปองพร้อมจำนวน หรือจัดซองสิทธิ์ตาม tier
- ซองมีสีตามระดับ เปิดแต่ละ tier แยกกัน แล้วเลือก/สุ่มได้ครั้งละ 1–หลายใบ เช่น EPIC 10 ใบ สุ่ม 4 แล้วเลือกอีก 6
- เลือกหลายแบบใส่รายการแล้วรับพร้อมกัน บันทึกทั้งครั้งใน transaction เดียว พร้อมจำกัดเพดานซ้ำและสิทธิ์แต่ละระดับ
- เก็บ snapshot ตั้งแต่วันส่ง การแก้ template ภายหลังไม่เปลี่ยนคำสัญญาในของขวัญ ใช้ requestId และ optimistic concurrency ป้องกันการรับซ้ำ/เกินสิทธิ์
- เปิดซองและพลิกผลหลัง API สำเร็จ รองรับ keyboard, focus และ reduced motion
- เพิ่มชุดวันเกิด 22 ใบ พร้อมงานบ้าน 8 ใบ เพดานงบตามคูปองรวม 6,900 บาท และซ่อน Romantic Set ด้วย soft delete

## ตัวกรองคลังคูปอง

- โหลดคลังคูปองครั้งเดียวแล้วกรองในหน้า เลือก tier แล้วไม่แสดงระดับอื่นปน แม้ API คืนรายการทั้งหมด
- เพิ่ม browser regression ครบห้าระดับที่ 390/1280 px ตรวจการสลับตัวกรองและการรักษาตะกร้า

## การอัปเกรด

- มี migration `AddGiftPacks`: เพิ่ม JSONB ของซอง, UUID กันส่งซ้ำ, concurrency บน GiftBatch, template วันเกิดใหม่ 3 แบบ และชุดวันเกิด
- Deploy API และยืนยัน migration สำเร็จก่อนปล่อย frontend ที่ใช้ endpoint ใหม่ ไม่เปลี่ยนคูปองที่มอบไปแล้ว
- Rollback migration ปฏิเสธเมื่อมีชุดของขวัญแล้ว เพื่อรักษาสิทธิ์ที่ยังไม่ได้รับ
- API เดิมยังใช้งานได้ รายละเอียดเพิ่มที่ [gift-packs.md](../../product/gift-packs.md)
- ซองใหม่ยังไม่มีอีเมลแจ้งเตือน งบรวมของชุดที่จัดเองต้องตรวจตามเงื่อนไขของแต่ละใบ

## ผลตรวจ

- Backend build และ 59 tests ผ่าน; Gmail setup 6 tests ผ่าน
- Frontend type check, lint, 7 tests และ production build ผ่าน
- Browser suites `test:ui`, `test:pocket`, `test:categories` และ `test:packs` ผ่านบน localhost
- ทดสอบ API/ฐานข้อมูลแยกจริง: เปิดซอง, รับหลายใบ, retry หลังคำตอบหาย, คำขอชนกัน, เงื่อนไข snapshot และวันหมดอายุ
- ตรวจภาพจริงที่ 390/1280 px และ reflow 320–1440 px หลักฐาน [gift-packs/verification.md](../gift-packs/verification.md)
