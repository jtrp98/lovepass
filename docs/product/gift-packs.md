# ซองคูปอง — เลือกให้เอง / ให้แฟนเลือกหรือสุ่ม

ชุดของขวัญประกอบด้วย **การ์ดข้อความจากคนให้** และ **ของขวัญที่จัดมาให้** ซึ่งเป็นคนละส่วนกัน ซองส่งการ์ดใช้สีชมพูของแบรนด์ ส่วนของขวัญเลือกจัดเป็นคูปองจริงหรือซองสิทธิ์ตาม tier ซองสิทธิ์ยังไม่ออกคูปองจนกว่าผู้รับเลือกหรือสุ่มสำเร็จ ใช้กับคู่รักที่จับคู่กันอยู่ตอนส่ง ผู้รับเดิมยังเปิดได้แม้สถานะคู่เปลี่ยนหลังส่ง

## รูปแบบ

- `FIXED` คนให้เลือกคูปองและจำนวนใส่ชุด ผู้รับเปิดการ์ดแล้วรับคูปองทุกใบเข้ากระเป๋าใน transaction เดียว
- `CHOICE` คนให้กำหนดแค่จำนวนสิทธิ์แต่ละ tier เช่น EPIC 10 ใบ ไม่ต้องเลือกคูปองหรือกำหนดเพดานซ้ำ ระบบเตรียมคูปองที่เปิดใช้งานทั้งหมดในระดับนั้นและตรึงเงื่อนไขตอนส่ง ผู้รับเลือกหรือสุ่มเองและเลือกแบบเดิมซ้ำได้จนครบสิทธิ์ ผู้รับเปิดการ์ดเพื่อดูของขวัญ แล้วเลือกเปิดซองสีของแต่ละ tier แยกกัน การเปิดซอง tier ยังไม่หักสิทธิ์ ซองเดิมยังใช้ตัวเลือกและเพดานที่บันทึกไว้
- หลังเปิด tier เลือกหรือสุ่มครั้งละ 1–N ใบได้ สุ่มกำหนดจำนวนแล้วกดครั้งเดียว ส่วนเลือกเองจัดรายการหลายแบบ/หลายจำนวนก่อนกดรับพร้อมกัน ใช้สิทธิ์ตามจำนวนรวมจาก tier เดียวใน transaction เดียว ถ้ารายการใดไม่ผ่านจะไม่ออกคูปองแม้แต่ใบเดียว
- การกดรับหรือสุ่มบันทึกสิทธิ์ทันที ไม่ใช่การแสดงตัวอย่าง เปลี่ยนผลหรือสุ่มใหม่โดยไม่ใช้สิทธิ์ไม่ได้ ทุกแบบที่ยังรับได้ในระดับนั้นมีโอกาสเท่ากันในการสุ่มแต่ละใบ ไม่ถ่วงน้ำหนักตามเพดานซ้ำ
- ก่อนกดรับ ผู้รับกางตั๋วอ่านเงื่อนไขได้ การสุ่มแสดงรายการที่มีโอกาสได้ทั้งหมดหลังเปิดซอง
- ซองหนึ่งมีสิทธิ์รวม 1–100 ใบ ตัวเลือกไม่เกิน 50 แบบ เพดานซ้ำไม่เกิน 100 ใบ ต้องมีตัวเลือกพอใช้สิทธิ์ทุกระดับ
- วันหมดอายุเดียวกันทั้งการเปิดซอง เลือก และใช้คูปอง การเลือกภายหลังไม่ต่อวันหมดอายุ
- Rarity ไม่ใช่งบรวม คนให้ต้องอ่านและยอมรับเงื่อนไขทุกตัวเลือกก่อนส่ง ไม่มีการอ่านงบจากข้อความหรือจำกัดงบอัตโนมัติ

## ชุดวันเกิด

Migration `AddGiftPacks` ซ่อน Romantic Set ด้วย soft delete และเพิ่มชุด **วันเกิดนี้ มีเราให้ทั้งปี** 22 ใบ: งานบ้าน 8 / กอด 3 / นวด 3 / ชม 1 / ไปหา 1 / ของขวัญ 1 / มื้อพิเศษ 1 / ดอกไม้ 1 / ของกินส่งถึงมือ 1 / หนังพร้อมขนม 1 / ถ่ายรูป 1

เพิ่ม template ใหม่ 3 ใบ ไม่แก้คลังเดิม: ไปหาเธอในวันของเรา (2,000 บาท), ของขวัญวันเกิดที่เธอเลือก (2,000 บาท), คืนหนังกับขนมของเรา (300 บาทรวมค่าเช่า) รวมเพดานงบทั้งชุด 6,900 บาท ปุ่มเริ่มจากชุดนี้ตั้งวันหมดอายุล่วงหน้าหนึ่งปีให้แก้ได้ การแก้จำนวนภายหลังทำให้งบรวมเปลี่ยนตามเงื่อนไขแต่ละใบ

## หน้าจอและการเคลื่อนไหว

- `/packs` ซองที่ได้รับ / ซองที่ส่ง แสดงสิทธิ์คงเหลือและผลที่บันทึกไว้
- `/packs/new` เลือกรูปแบบ: FIXED เลือกคูปองและจำนวน ส่วน CHOICE กำหนดจำนวนแต่ละ tier เท่านั้น แล้วตรวจซองก่อนปิดผนึก
- การ์ดส่งของขวัญและซองสิทธิ์ตาม tier แยกเป็นคนละวัตถุ ซอง tier ย้อมสีจาก rarity token เดียวกับตั๋ว (COMMON ชมพู / RARE ฟ้า / EPIC ม่วง / LEGENDARY ทอง / MYTHIC พาสเทลฟอยล์) มีตราครั่ง ฝาซองเปิดหลัง API สำเร็จเท่านั้น คูปองสุ่มพลิกเปิดหลังบันทึกทั้งครั้งสำเร็จ
- การโหลดซองที่เคยเปิดแสดงสภาพเปิดโดยไม่เล่นซ้ำ การสับตั๋วระหว่างรอเล่นจำกัดรอบ เคารพ reduced motion มีปุ่มคีย์บอร์ด ข้อความสถานะและย้าย focus ไปผลที่ได้รับ
- ถ้าไม่ทราบผลเพราะเครือข่ายขาด ต้องลองคำขอเดิมหรือโหลดผลล่าสุดก่อนเลือกใหม่

## API contract

ทุก endpoint ต้องล็อกอิน ใช้ ProblemDetails เดิมของระบบ

สร้างซอง CHOICE ส่ง `options: []` แล้ว backend เตรียมคูปองที่เปิดใช้งานทั้งหมดใน tiers ที่ระบุ แต่ละแบบรับซ้ำได้เท่าจำนวนสิทธิ์ของ tier หาก tier ไม่มีคูปองจะตอบ 409 ส่วน FIXED ยังต้องส่ง options เสมอ รองรับ client เก่าที่ส่ง options ของ CHOICE มาเองโดยใช้ตัวเลือกและเพดานตามเดิม

| Endpoint | ข้อมูล |
| --- | --- |
| `GET /api/v1/gift-packs` | ซองที่ส่งหรือได้รับ ล่าสุดไม่เกิน 200 ซอง |
| `POST /api/v1/gift-packs` | `requestId` UUID, `receiverId`, `name` ≤100, `mode`, `expiresAt` UTC, `message` ≤500, `options: [{couponTemplateId, limit}]`, `quotas: [{rarity, quantity}]` (FIXED ส่ง quotas ว่าง) |
| `POST /api/v1/gift-packs/{id}/open` | ผู้รับเท่านั้น เรียกซ้ำไม่ออกคูปองเพิ่ม |
| `POST /api/v1/gift-packs/{id}/tiers/{rarity}/open` | เปิดซอง tier แยกจากการ์ด ไม่หักสิทธิ์ เปิดซ้ำคืน state เดิม |
| `POST /api/v1/gift-packs/{id}/draws` | `requestId` UUID, `rarity`, `quantity` 1–100 (default 1), `couponTemplateIds` รายการ ID หนึ่งตัวต่อหนึ่งใบ (ส่ง ID ซ้ำได้ตามเพดาน), หรือ `couponTemplateId` ชนิดเดียว ×quantity; ไม่ส่งทั้งคู่ = สุ่มตาม quantity, `expectedDrawCount` เป็นจำนวนที่รับแล้วในหน้าปัจจุบัน แต่ละ intent ใช้ UUID เดิมและ payload เดิมเมื่อ retry |

ผลลัพธ์ `GiftPack`: `id`, `name`, `mode`, `message`, `expiresAt`, `openedAt` (การ์ด), `openedTiers` (ชื่อ tier ที่เปิดแล้ว), `isSender`, `total`, `quotas`, `options: [{couponTemplateId, limit, selected, coupon}]`, `draws: [{requestId, couponTemplateId, rarity, random}]` โดย `coupon` เป็น snapshot ของชื่อ รายละเอียด เงื่อนไข rarity category effect และ metaLocked ตอนส่ง ก่อนผู้รับเปิดการ์ดจะไม่ส่ง options/draws และในโหมด CHOICE ส่งตัวเลือกเฉพาะ tier ที่เปิดแล้วเท่านั้น หนึ่ง batch มี draw ตามจำนวนใบ โดยใช้ requestId เดียวกันเพื่อผูกผลทั้งครั้ง

สร้างซองใช้ UUID ไม่ซ้ำในฐานข้อมูลและ hash payload: retry เดิมคืนซองเดิม ใช้ UUID เดิมกับข้อมูลอื่นตอบ 409 การ draw ซ้ำคืน state ปัจจุบันพร้อมผลของ UUID เดิม ไม่ใช้สิทธิ์เพิ่ม ทั้ง open/draw ใช้ optimistic concurrency (`xmin`) บน GiftBatch และ transaction ครอบการออกคูปองกับบันทึกผล ถ้าชนกันตอบ 409 แล้วให้โหลดหรือ retry คำขอเดิม

`GiftBatch.PackPlan` เก็บ JSONB ของ snapshot, quotas, openedTiers, ผลแต่ละใบ และ fingerprint ของ batch แต่ละครั้ง `PackKey` เป็น UUID ของคำขอสร้างชุดของขวัญ ชุดที่เลือกบางส่วนยังออกคูปองตามสิทธิ์ที่บันทึกสำเร็จไว้แล้ว รายการของขวัญเดิมใช้ endpoint เดิม ส่วนชุดดูที่ `/packs` ไม่สร้างรายการว่างซ้ำใน `/sent-gifts`

Migration rollback ปฏิเสธเมื่อมีซองแล้ว เพื่อไม่ลบคำสัญญาที่ยังไม่ได้เลือก ไม่มีการส่งอีเมลสำหรับซองในรุ่นนี้ ผู้รับเข้าดูได้จากกระเป๋าคูปองหรือเมนูซองคูปอง
